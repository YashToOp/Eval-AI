----------------------------------------------------------------
1. PURPOSE OF THE BENCHMARK
----------------------------------------------------------------

1.1 What this corpus is for
This corpus is an evaluation instrument, not a leaderboard and
not training data. Its job is to expose weaknesses in detectors:
hidden assumptions, calibration failures, feature leakage,
overfitting to particular generators or domains, brittle
heuristics, and silent degradation under distribution shift. A
detector that scores well here has survived a stress test. It
has not been proven correct.

1.2 What it measures
(a) Generalization: behavior on generators, domains, formats,
    lengths, and languages absent from detector training data.
(b) Calibration: whether reported probabilities mean what they
    claim, measured overall, per category, and per length bucket.
(c) Worst-case behavior: per-cell minima, never corpus averages.
    A deployed detector is exactly as good as its worst cell.
(d) Robustness: defined, graceful behavior on adversarial
    transforms, degenerate inputs, and encoding attacks. No
    crashes, no NaN scores, no silent truncation.
(e) Fairness: false positive parity across native and non-native
    writers and across registers and dialects.
(f) Honesty about uncertainty: correct low-confidence output on
    texts that are information-theoretically undecidable.

1.3 Threat model
Three regimes, all in scope:
R1 Cooperative: text produced by normal workflows with no
   attempt to evade detection.
R2 Evasive: text deliberately transformed to defeat detection
   (paraphrase attacks, humanizer tools, Unicode manipulation,
   suppression of known "AI tells").
R3 Incidental hybrid: ordinary human-AI collaboration (polish,
   grammar fixes, co-writing) with no adversarial intent. This
   regime dominates real traffic and is where naive binary
   framing causes the most damage.

1.4 Non-goals and responsible use
The benchmark does not certify any detector as evidence for
accusing an individual. Detector outputs are probabilistic
signals about a writing process, and this corpus deliberately
contains cells where the only correct answer is "cannot tell".
Any downstream policy built on a detector evaluated here must
inherit that limitation explicitly.

1.5 Design principles
P1 Axes, not lists. The corpus is a factorial space (authorship
   process x domain x format x length x language x generator
   configuration x adversarial transform x provenance tier).
   Named categories are reporting clusters over that space. Flat
   category lists create coverage illusions.
P2 Provenance over plausibility. A sample's label comes from its
   documented production history, never from how the text looks.
P3 Label the process, not the artifact. The same string can be
   produced by a human or a model. Only the process is knowable
   ground truth.
P4 Report worst case. Averages hide exactly the failures this
   corpus exists to find.
P5 Every discovered bug becomes a permanent regression test
   (Section 8). No bug reappears without failing CI.
P6 Future-proof via invariants. Do not encode 2024-2026 model
   stereotypes (em dash density, "delve", list addiction,
   uniform paragraph rhythm) as assumptions. Those are transient
   properties of specific model generations. The durable
   invariants are: hybrid authorship is inherently ambiguous;
   short texts carry little signal; both generator style and
   human style drift over time; calibration is measurable in any
   era; process provenance is the only stable ground truth. The
   benchmark tests whether a detector depends on transient
   stereotypes by pairing every alleged "tell" with human
   counterexamples that have the tell and AI counterexamples
   that lack it.

2. DATASET STRUCTURE
----------------------------------------------------------------

2.1 Axes
Every sample is a point in the following space. Axes are
recorded independently in metadata (Section 5) so that results
can be sliced along any axis, not only along named categories.

AX1 Authorship process: HUMAN, AI, AI_HUMAN_EDITED,
    HUMAN_AI_EDITED, COLLAB_MIXED (taxonomy in Section 4.1).
AX2 Domain/register: casual, technical, academic, creative,
    legal, medical, financial, marketing, support, engineering
    communication (issues, reviews, RFCs, mailing lists).
AX3 Format: prose, email, chat/IM, forum post, markdown,
    bullet-dominant, table-dominant, JSON, YAML, code-mixed.
AX4 Length bucket: B25, B50, B100, B250, B500, B1000 (2.5).
AX5 Language: en-native, en-nonnative, mixed/code-switched,
    non-English (expansion, Section 10).
AX6 Generator configuration: model family, model version,
    prompt style, decoding parameters (AI-involved samples only).
AX7 Adversarial transform: none, or one or more documented
    transforms from Section 7.
AX8 Provenance tier: T0-T3 (Section 4.2).

2.2 Directory layout
/corpus
  manifest.json           corpus version, split definitions,
                          per-file SHA-256 checksums, axis
                          vocabularies
  /samples/
    track_h.jsonl         human-only
    track_a.jsonl         AI-only
    track_x.jsonl         hybrid
    track_v.jsonl         adversarial
    track_f.jsonl         format and register shift
    track_e.jsonl         edge cases and degenerate inputs
    track_u.jsonl         undecidability probes
  /regression/
    BUG-YYYYMMDD-NNN.jsonl  one file per confirmed bug
  /generation_configs/    full prompts, parameters, seeds, and
                          raw API responses for AI-involved
                          samples
  /provenance/            source documentation, edit-session
                          diffs, attestations, licenses
  /docs/                  this specification, changelogs,
                          annotation guidelines

2.3 Splits
DEV    Public. For detector debugging. Assume contaminated: any
       detector may have trained on it. Never report DEV numbers
       as results.
TEST   Versioned and semi-public. Frozen per release. Reported
       in evaluations with the corpus version string.
HIDDEN Never published. Evaluated only through the harness on a
       schedule, with quantized score reporting (Section 8.6) to
       slow down benchmark overfitting. Rotated: a slice of
       HIDDEN is promoted to TEST at each major release and
       replaced with fresh samples.

2.4 Versioning
Semantic versioning of the corpus. MAJOR: label taxonomy or
scoring change. MINOR: new categories or samples. PATCH: label
corrections. Releases are immutable and checksummed. Every
reported result cites the exact corpus version.

2.5 Length buckets
B25 (20-30 words), B50 (40-60), B100 (85-115), B250 (215-285),
B500 (430-570), B1000 (850+ words). Word count is computed by
the harness tokenizer-independent counter (whitespace-delimited
after Unicode normalization) and stored in metadata; bucket
membership is part of ground truth. Every named category must
populate every bucket unless the category definition makes a
bucket impossible (e.g., table-dominant samples below B100);
such exemptions are recorded in the manifest.

2.6 Cell sizing and statistical power
A cell is (category x length bucket x split). Phased targets:
v1.0: TEST >= 10 samples per cell, DEV >= 5, HIDDEN >= 5.
v1.1: TEST >= 25 per cell.
v2.0: TEST >= 50 per cell.
Aggregate constraint, independent of cells: the pooled human
TEST set must contain >= 3,000 samples in v1.0 and >= 10,000 by
v2.0, because false positive rates in the 0.5-1.0 percent range
cannot be estimated from small negative pools (estimating
FPR = 1 percent within +/- 0.5 points at 95 percent confidence
requires on the order of 1,500-4,000 negatives). Adversarial
cells at n = 10-25 have wide confidence intervals; the harness
must print intervals (Wilson score) next to every cell metric so
small-n cells are never over-read.

2.7 Generator sampling
The full factorial over model x prompt style x decoding
parameters is infeasible. Use a covering design: every pairwise
combination of (model family, prompt style) and (model family,
decoding regime) must appear at least once per domain. Sample
the remaining space by stratified randomization with logged
seeds. The covering matrix is checked mechanically at release
time (Section 9.1).

2.8 Topic pairing
Topic is a confound: detectors can learn topic instead of
authorship. Wherever feasible, samples are produced in matched
topic sets: the same topic prompt realized as (a) human text,
(b) AI text from multiple generators, (c) hybrids. Matched sets
share a topic_group_id in metadata so evaluators can measure
within-topic discrimination separately from cross-topic
performance.

3.7 TRACK U: UNDECIDABILITY PROBES
Short, generic, low-entropy texts with verified provenance in
BOTH classes: e.g., "Thanks! Sounds good, see you Monday."
collected from a T1 human session and independently produced by
a generator. Ground truth exists per sample, but the corpus
guarantees the two classes are indistinguishable at the string
level for this track. Expected detector behavior is calibrated
low confidence; scoring is via overconfidence rate (9.3), not
accuracy. This track exists to fail any detector that
manufactures certainty.


----------------------------------------------------------------
4. GROUND-TRUTH REQUIREMENTS
----------------------------------------------------------------

4.1 Label taxonomy
Binary labels are insufficient and are the root cause of most
detector evaluation failures. The primary label is the
authorship process:

  HUMAN            No generative model involvement at any stage.
                   Spellcheck and non-generative tools allowed;
                   generative rewrite suggestions are not.
  AI               Fully model-generated; post-generation
                   changes limited to whitespace.
  AI_HUMAN_EDITED  Model-origin base, human modifications.
  HUMAN_AI_EDITED  Human-origin base, model modifications.
  COLLAB_MIXED     Interleaved authorship without a single base.

Numeric fields accompany the label:
  ai_token_share   [0.0-1.0], computed from stored diffs, the
                   fraction of final tokens of model origin.
  span_map         Required for COLLAB_MIXED and splice
                   categories: list of [start_char, end_char,
                   origin] entries.

4.2 Provenance tiers
  T0  Verifiably pre-LLM: archival source with a capture date
      before 2020 from an independent archive (checksummed).
  T1  Process-logged: keystroke logs, screen recordings, or
      full edit-session capture; for AI content, complete API
      request/response records.
  T2  Attested: signed statement from the author describing the
      process, plus plausibility review. Used only where T0/T1
      are impossible.
  T3  Heuristic: provenance inferred. NOT admissible as ground
      truth in TEST or HIDDEN. Allowed in DEV only, flagged
      noisy_label=true.

Cell requirements: all human categories in TEST/HIDDEN require
T0, T1, or T2. All fairness-gated categories (H-14, H-17)
require T1 or T2. All hybrid categories require T1 (the diff IS
the label). All AI categories require T1 by construction.

4.3 Human sourcing rules and the contamination trap
Post-2022 web text is presumed contaminated: autocomplete,
grammar tools with generative rewriting, and quiet AI assistance
are pervasive. Therefore human ground truth comes from (a)
pre-2020 archives (T0), or (b) freshly commissioned writing
under logging (T1), or (c) attested contributions (T2). The T0
pool alone is insufficient because human style drifts (people
now write with idioms absorbed from model output); H-20 exists
to keep the human distribution current, and the human baseline
is re-estimated annually (Section 10).

4.4 AI sourcing rules
Every AI-involved sample stores: model identifier and exact
version string, provider, request date, full prompt including
system prompt, all decoding parameters, seeds where supported,
and the raw unmodified response. Regeneration must be attempted
at audit time; where providers are nondeterministic, the stored
raw response is authoritative.

4.5 Hybrid construction protocol
Hybrids are produced in controlled sessions: base text captured,
every edit round captured, final diff computed and stored under
/provenance/. ai_token_share is computed mechanically from the
diff chain, not estimated by annotators. Editing instructions
given to humans (e.g., "fix grammar only" vs "rewrite freely")
are recorded, because the instruction defines the category.

4.6 Annotation and adjudication
Process labels come from provenance, not from readers. Human
annotation is used only for metadata that requires judgment
(register tags, difficulty, PII checks, quality screening). All
judgment fields are dual-annotated; Cohen's kappa >= 0.8
required per field per release; disagreements adjudicated by a
third senior annotator; adjudication decisions logged.

4.7 Required per-sample ground truth
Every sample must carry: unique ID, category ID, length bucket
and exact count, source type, provenance tier, expected label
(4.1) with numeric fields, difficulty (4.8), rationale (one to
three sentences: why this sample belongs to its class), and
target_weakness (which detector assumption or failure mode this
sample probes). Samples missing any field fail release
validation.

4.8 Difficulty scale
  D1 trivial      Any competent detector should succeed.
                  Doubles as a canary for harness bugs.
  D2 easy         Mild shift from common training conditions.
  D3 moderate     Realistic deployment difficulty.
  D4 hard         Cross-distribution or lightly adversarial.
  D5 adversarial  Deliberately evasive or near-undecidable;
                  scored on robustness and calibration, and
                  detectors are not expected to approach
                  perfect accuracy here.

4.9 Decontamination
Before release: 13-gram containment checks of every sample
against (a) known public detector training sets (e.g., HC3,
GPT-2 output corpus, M4, RAID, MGTBench releases), (b) common
pretraining corpus indices where available, (c) the DEV split.
Any TEST/HIDDEN sample with a contiguous 50+ character overlap
with a public detection corpus is replaced or moved to DEV.
Results of the scan ship in the manifest.

4.10 PII and licensing
All samples pass automated plus manual PII screening; email
corpora are scrubbed with named-entity replacement, and medical
or student content is synthetic, licensed, or T1-commissioned.
Every sample records a license field; unlicensed material does
not enter the corpus.

5. METADATA FORMAT
----------------------------------------------------------------

5.1 Container
JSON Lines, one object per sample, UTF-8. Field order fixed for
diff-friendliness. Schema versioned as metadata_schema_version.

5.2 Schema (v1)
  id                  string  Stable ID: TRACK-CAT-BUCKET-NNNN,
                              e.g., "V-05-B250-0031".
  schema_version      string
  corpus_version      string
  split               enum    dev | test | hidden
  text                string  The sample, byte-exact. Never
                              normalized in storage; all
                              normalization happens (and is
                              tested) inside detectors.
  category            string  e.g., "V-05".
  track               enum    H | A | X | V | F | E | U
  domain              string  AX2 vocabulary.
  format              string  AX3 vocabulary.
  language            string  AX5 vocabulary.
  length_words        int
  length_bucket       enum    B25..B1000
  label               enum    Section 4.1 taxonomy.
  ai_token_share      float   0.0-1.0; 0.0 for HUMAN, 1.0 for
                              AI, diff-derived otherwise.
  span_map            array   [[start,end,"human"|"ai"],...] or
                              null.
  source_type         string  Free-form provenance summary,
                              e.g., "commissioned_writer_T1",
                              "archive_2017_mailing_list".

6. EXPECTED FAILURE MODES
----------------------------------------------------------------

6.1 Detector family taxonomy (referenced throughout)
  DF1 Likelihood/perplexity zero-shot (GLTR, DetectGPT,
      Fast-DetectGPT, Binoculars style: curvature, rank, or
      cross-model likelihood statistics).
  DF2 Supervised fine-tuned classifiers (RoBERTa-style trained
      on paired human/AI corpora).
  DF3 Stylometric feature systems (burstiness, sentence-length
      variance, punctuation and function-word statistics,
      hand-built heuristics).
  DF4 LLM-as-judge (zero/few-shot prompting of a model to
      classify text).
  DF5 Watermark detectors (statistical signals embedded at
      generation time).
  DF6 Retrieval/memorization systems (near-duplicate search
      against known model outputs).
  DF7 Ensembles and meta-classifiers over DF1-DF6.

6.2 Failure analyses
Format per entry: categories covered; what a weak detector will
do; why it fails; the misleading feature; vulnerable families;
required evaluator response.

FM-01  H-02, H-08, H-09, H-13, V-03 (fluent, structured human)
  Weak behavior: labels polished human prose as AI with high
  confidence. Why: training negatives skew casual; the detector
  learns "formal and clean means AI". Misleading feature:
  fluency, structural regularity, perfect grammar. Vulnerable:
  DF2, DF3, DF4. Response: treat FPR on these cells as primary
  release metric; retrain with edited-human negatives; never
  tune thresholds on casual-human negatives alone.

FM-02  H-14, H-17 (non-native and student writing)
  Weak behavior: elevated false positives on exactly the
  populations most harmed by accusation. Why: limited
  vocabulary range and conventional phrasing lower perplexity
  and flatten stylometric variance. Misleading feature: low
  lexical diversity, template-like syntax. Vulnerable: DF1,
  DF3, DF2 trained on native-fluent negatives. Response:
  fairness gate (9.2) is release-blocking; report these cells
  separately in every evaluation; prohibit deployment framing
  that treats these scores as individual evidence.

FM-03  H-15, E-12 (low-perplexity and copied human text)
  Weak behavior: boilerplate, legal templates, and verbatim
  documentation flagged as AI. Why: DF1 conflates "statistically
  predictable" with "machine-generated"; memorized or standard
  text is maximally predictable. Misleading feature: low
  perplexity. Vulnerable: DF1; DF6 inverts the error by matching
  reused text to model outputs that also memorized it. Response:
  require a predictability-vs-provenance distinction in detector
  design; any confident AI label on E-12 is an automatic
  regression entry.

FM-04  H-16, V-11 (human text carrying "AI tells")
  Weak behavior: keys on em dashes, section headers, dated
  vocabulary ("delve", "leverage") and fires. Why: feature
  leakage from a transient stereotype; humans wrote this way
  before models and still do. Misleading feature: dated lexical
  and formatting tells. Vulnerable: DF3 primarily, DF2 trained
  on recent scrapes, DF4 with tell-based prompting. Response:
  the paired design (V-10 vs V-11) isolates leakage; a detector
  whose score moves substantially on the tell axis while process
  is held constant fails 9.3(e).

FM-05  A-09, A-10, V-01, V-10 (constrained and steered AI)
  Weak behavior: misses AI generated under style constraints,
  high temperature, penalty settings, or tell suppression. Why:
  every surface heuristic the detector uses is under the
  generator's control. Misleading feature: burstiness and tell
  absence read as human. Vulnerable: DF3 near-fatally; DF2 out
  of distribution; DF1 partially (high temperature raises
  perplexity toward the human range). Response: measure
  detection as a function of decoding parameters and report the
  curve, not a point; assume R2 attackers control decoding.

FM-06  V-04, H-12, H-18, E-08 (messy AI vs genuinely messy human)
  Weak behavior: reads typos, fragments, false starts, and
  hedges as proof of humanity, and their absence as proof of AI.
  Why: error patterns are trivially promptable; meanwhile
  transcribed and drafted human text supplies the same surface.
  Misleading feature: surface noise as authorship signal.
  Vulnerable: DF3, DF4. Response: noise features may inform but
  must not dominate; the paired cells make over-weighting
  measurable.

FM-07  X-01..X-09 (hybrids)
  Weak behavior: forces a binary answer, flip-flops across
  near-identical samples, or scores mid-probability without
  meaning it. Why: the true state is genuinely mixed; binary
  training objectives have no representation for it. Misleading
  feature: whichever segment dominates the feature window.
  Vulnerable: all families; DF2 and DF4 most confidently wrong.
  Response: evaluate hybrids only under the task definitions in
  9.3 (involvement detection and origin attribution, plus span
  localization where supported); never average hybrids into a
  binary accuracy number.

FM-08  X-10, X-11 (summaries across the boundary)
  Weak behavior: labels the AI summary human because the ideas
  and vocabulary are human-sourced, or labels the human summary
  AI because the content mirrors model output. Why: content
  features leak into what should be a process judgment.
  Misleading feature: topical and lexical overlap with the
  source. Vulnerable: DF2, DF6, DF4. Response: matched
  topic_group_id slicing separates content signal from process
  signal; report both.

FM-09  V-05, V-06, V-14 (paraphrase, humanizers, back-translation)
  Weak behavior: detection collapses after laundering. Why:
  likelihood and watermark statistics are properties of the
  original decoding step and do not survive resampling by
  another model. Misleading feature: post-transform fluency
  profile. Vulnerable: DF5 (watermarks largely destroyed), DF1,
  DF2. Response: report detection as a function of transform
  strength; laundering resistance is a separate headline metric
  and a known open problem, so honest reporting beats silent
  averaging.

FM-10  V-07, V-08, V-09, E-13 (encoding attacks and degenerate
       inputs)
  Weak behavior: crashes, NaN, tokenizer explosion, silent
  truncation, or confident labels on unclassifiable input; or
  normalization asymmetries flip labels. Why: preprocessing
  assumptions (clean UTF-8, NFC, visible characters) are
  attacker-controlled. Misleading feature: none; this is
  plumbing. Vulnerable: all families; DF2/DF1 via tokenizers.
  Response: robustness harness (9.3(d)) requires defined output
  for 100 percent of these inputs; every crash is a P1
  regression entry.

FM-11  V-12 (prompt injection inside samples)
  Weak behavior: an LLM-judge follows instructions embedded in
  the text under evaluation. Why: DF4 shares an instruction
  channel with its input. Misleading feature: imperative text
  addressed to the classifier. Vulnerable: DF4, and DF7
  ensembles containing DF4. Response: injection success rate
  must be 0 on this category; any nonzero rate blocks release of
  a judge-based component.

FM-12  A-11, A-12 (held-out and legacy generators)
  Weak behavior: sharp accuracy drop on model families absent
  from training, or on older-generation output that lacks
  frontier style. Why: DF2 learns generator-specific artifacts,
  not generation itself; DF1 depends on scorer-generator
  affinity. Misleading feature: family-specific stylistic
  fingerprints. Vulnerable: DF2, DF1, DF6. Response: the G9
  delta (known-model performance minus held-out performance) is
  a standing headline metric; large deltas indicate overfitting
  to generators, not detection ability.

FM-13  V-17 (judge self-preference)
  Weak behavior: an LLM judge systematically misclassifies its
  own family's output (either direction). Why: self-recognition
  and self-preference asymmetries in evaluator models.
  Misleading feature: familiarity of the judge with its own
  distribution. Vulnerable: DF4. Response: report per-family
  confusion asymmetry; never deploy a judge blind to this
  measurement.

FM-14  F-01..F-20 (format and register shift)
  Weak behavior: performance varies wildly across formats;
  markdown, JSON, and table content is mis-scored because
  structure dominates features; terse registers (F-07, F-10)
  degrade to chance without confidence dropping. Why: format
  tokens swamp stylistic signal; training data underrepresents
  most registers. Misleading feature: structural tokens.
  Vulnerable: DF3, DF2, DF1. Response: per-format reporting is
  mandatory; confidence must fall where accuracy falls
  (calibration per cell), and structure-stripping ablations are
  recommended detector-side.

FM-15  Short buckets B25/B50 across all tracks, and Track U
  Weak behavior: confident labels on 25-word texts. Why: the
  mutual information between a short string and its authorship
  process is small; confident output is fabricated certainty.
  Misleading feature: any feature at all, over-trusted at short
  length. Vulnerable: all families, DF4 especially (fluent
  rationalization of noise). Response: overconfidence rate on
  Track U and calibration per length bucket are release gates;
  detectors should support abstention below an evidence
  threshold.

FM-16  X-12, X-13, X-14, E-06 (translation and code-switching)
  Weak behavior: translationese scored as AI regardless of
  source; code-switched human text flagged. Why: MT output has
  machine statistics whatever the source authorship; mixed
  language breaks monolingual features. Misleading feature:
  machine-translation register. Vulnerable: DF1, DF2, DF3.
  Response: keep MT policy explicit in the manifest (X-12 label
  decision), report translation cells separately, and treat
  code-switch false positives as fairness-adjacent (9.2).

7. ADVERSARIAL GENERATION INSTRUCTIONS
----------------------------------------------------------------

General rules for all recipes: log every parameter, seed, tool
version, and date; store raw pre-transform and post-transform
text; store transform positions where applicable; generate
against matched topic sets (2.8) so adversarial cells have
non-adversarial twins. Attack content is produced for evaluation
only and stays inside the corpus pipeline.

7.1 Paraphrase and laundering (V-05, V-14, V-06)
  a. Generate base AI text (A-01 conditions).
  b. Paraphrase with a dedicated paraphraser or a second model
     family at three strengths: light (lexical substitution,
     order preserved), medium (sentence-level rewrite), heavy
     (document-level restructure). Record the paraphrase prompt
     verbatim.
  c. Recursive variant: repeat medium paraphrase 3x, storing
     every intermediate.
  d. Back-translation: pivot through 1 and 3 languages with a
     named MT system; log language chain.
  e. Humanizer tools: process through named commercial services;
     capture tool name, settings, and date (tool behavior
     drifts; the date is part of the sample identity).

7.2 Decoding sweeps (A-10)
Grid per generator where the API allows: temperature {0.0, 0.3,
0.7, 1.0, 1.3}, top_p {0.9, 0.95, 1.0}, frequency/presence
penalty {0, 0.4, 0.8}, plus provider default. Sample the grid by
covering design (2.7). Identical prompts across the grid so
decoding is the only variable.

7.3 Style constraint prompting (A-09, V-01, V-04)
Maintain a versioned instruction library, including at minimum:
vary sentence length aggressively; forbid lists and headers;
forbid em dashes and semicolons; require occasional fragments;
require one plausible typo per ~120 words; require hedged
memory ("if I remember right..."); require mid-thought
self-correction; write as a specific persona with background
details. Store the exact instruction set per sample. Do not
hand-edit outputs; if a model fails the constraints, keep or
regenerate, never repair (human repair would silently create a
hybrid).

7.4 Tell suppression and injection (V-10, V-11)
Maintain tells-YYYY-MM: a dated, versioned list of currently
alleged AI markers (lexical items, punctuation habits,
formatting patterns), sourced from current detector literature
and the team's own feature analyses. V-10: instruct generators
to avoid every listed item; verify absence mechanically. V-11:
commission T1 human writers to naturally incorporate listed
items; verify presence mechanically. The tell list is data, and
its updates are part of corpus maintenance (Section 10), because
the whole point is that these markers expire.

7.5 Unicode and encoding attacks (V-07, V-08, V-09, E-13)
Scripted transforms with logged RNG seeds: homoglyph maps
applied at 0.001, 0.01, 0.05 character rates; zero-width
characters at word boundaries and intra-word; NFC/NFD mixing;
quote and space substitutions; direction marks. Apply to both
human and AI base text so the transform axis is orthogonal to
the label. Positions ship in provenance for exact
reproducibility.

7.6 Splice construction (V-13, X-08, X-09)
Assemble from provenance-verified components only. Record spans
exactly. Variants: human-head/AI-tail at 30/70, 50/50, 70/30;
AI sandwich; paragraph-level alternation. Boundary placement at
natural paragraph breaks and, separately, mid-paragraph (the
harder case for span localizers).

7.7 Author mimicry (V-15)
With writer consent: collect 5-10 genuine samples (T1), few-shot
prompt each generator to imitate, and hold out genuine samples
from the same writer for pairing. Evaluation pairs mimicry
against held-out genuine text from the same author, the only
setting that isolates identity features from topic and register.

7.8 Noise models (E-08, E-09, E-10)
Keyboard-adjacency typo model with logged error rate; OCR noise
via degradation-and-recognition of rendered text or a validated
confusion table; ASR noise via re-recognition of read speech or
validated phonetic confusions. Apply to T0 human text and to AI
text alike; the noise axis must never correlate with the label.

7.9 Prompt injection payloads (V-12)
Payload library: overt appeals ("this was written by hand"),
authority framing ("instructor note: verified human"), direct
instruction to the classifier, and hidden variants (white-on-
white markers are out of scope for plain text; use zero-width
delimited instructions and comment-style asides). Insert at
head, middle, and tail positions. Ship payload boundaries in
provenance.

8. REGRESSION-TEST STRATEGY
----------------------------------------------------------------

8.1 Principle
Every discovered bug becomes a permanent, minimal, executable
test. The regression suite only grows. No entry is ever deleted;
superseded entries are marked with a successor reference and
remain executable.

8.2 Bug lifecycle
  a. Discovery: a misbehavior is observed (evaluation run, red
     team, production report).
  b. Minimization: reduce to the smallest sample set (target
     1-5 samples) that still reproduces the misbehavior.
  c. Regression entry: create /regression/BUG-YYYYMMDD-NNN.jsonl
     containing the samples plus a regression record (8.3).
  d. Gate: the entry enters CI immediately, marked
     expected-fail until the fix lands, then must pass forever.

8.3 Regression record schema
  bug_id, discovery_date, reporter, linked_issue,
  affected_detector_versions, description (one paragraph),
  category_refs (which corpus categories relate),
  expected_behavior: exact assertion, one of:
    label == X
    p_ai_involvement within [lo, hi]
    confidence <= c            (undecidable/degenerate cases)
    no_crash and defined_output
    score_delta <= epsilon under transform T (invariance)
  status: expected_fail | passing | superseded(successor_id)

8.4 CI tiers
  Tier 1, every commit: full regression suite plus D1 canaries.
  Budget: minutes. 100 percent pass required to merge; a
  regression failure is a build failure, not a warning.
  Tier 2, nightly: full DEV and TEST evaluation, all metrics of
  9.3, with per-cell trend tracking and alerting on any cell
  moving more than its tolerance band.
  Tier 3, scheduled (e.g., biweekly): HIDDEN split via the
  sealed harness. Results reported quantized (8.6).

8.5 Metamorphic and property-based tests
Standing invariance suite, run in Tier 1 on a fixed sample
panel. For each transform, assert |score_before - score_after|
<= epsilon:
  trailing whitespace and newline changes (epsilon = 0.00)
  Unicode NFC normalization of already-clean text (0.00)
  straight/curly quote substitution (0.02)
  single mid-word typo in a B500 sample (0.05)
  reordering of two independent paragraphs (0.05)
Also directional properties: appending verified human text to a
human sample must not increase p_ai; duplicating a sample's
content must not change its label. Property tests double as
fuzz targets: random degenerate inputs (E-13 generators) must
never crash the pipeline.

8.6 Anti-overfitting controls for the benchmark itself
The benchmark is also a system that can be gamed. Controls:
HIDDEN results are reported rounded to 0.5-point granularity
with a per-quarter query budget per detector line; HIDDEN
rotates at major releases; TEST is frozen and versioned so
claimed numbers are auditable; any detector change justified
purely by a TEST cell delta triggers a review for
benchmark-specific tuning.

8.7 Golden outputs and drift alarms
For each released detector version, store full per-sample score
vectors on TEST. Nightly runs diff against golden vectors;
unexplained per-sample score drift beyond tolerance raises an
alarm even when aggregate metrics look flat. Aggregate stability
with per-sample churn is a classic symptom of a silent bug.

8.8 Reproducibility
The harness pins: corpus version and checksums, detector version,
scorer model versions for DF1/DF4 components, random seeds, and
environment lockfiles. A regression must be reproducible from
the repository alone.

9. ACCEPTANCE CRITERIA
----------------------------------------------------------------

9.1 Corpus release acceptance (the benchmark itself)
  a. Coverage: every (category x bucket x split) cell meets the
     phase targets of 2.6; the covering matrix of 2.7 verifies
     mechanically; exemptions listed in the manifest.
  b. Provenance: 100 percent of TEST/HIDDEN samples at T0/T1/T2;
     hybrid cells 100 percent T1; provenance refs resolve.
  c. Annotation quality: kappa >= 0.8 on all judgment fields;
     adjudication log complete.
  d. Decontamination scan (4.9) passed and shipped.
  e. PII and license fields present and screened on every
     sample.
  f. Canary solvability: a public baseline detector achieves
     >= 95 percent on D1 cells; failure indicates broken labels
     or harness, not a hard benchmark.
  g. Metadata validation: schema-complete, including rationale
     and target_weakness on every sample.
  h. Every category in Section 3 has at least one entry in the
     failure-mode map (Section 6.2) and at least one adversarial
     or edge neighbor that stresses the same assumption.

9.2 Fairness gates (release-blocking for detectors)
  a. FPR on H-14 (non-native) <= 1.25x FPR on matched native
     cells, at the deployed threshold; both reported always.
  b. FPR on H-17 (student writing) reported separately at the
     deployed threshold with confidence intervals.
  c. No confident-AI labels (p > 0.9) on more than 1 percent of
     any human T0/T1 cell.

9.3 Detector evaluation protocol
Tasks are evaluated separately and never averaged together:
  T1 Pure discrimination: HUMAN vs AI, hybrids excluded.
  T2 Involvement detection: HUMAN vs any AI involvement.
  T3 Origin attribution: base-process classification over the
     full taxonomy (4.1).
  T4 Span localization: for detectors that support it, span-F1
     against span_map on COLLAB_MIXED and splice cells.
Required reporting, per task:
  a. Primary: TPR at fixed FPR = 1 percent and FPR = 0.5
     percent, per category and per length bucket, with Wilson
     intervals; the corpus-level headline is the WORST cell, and
     the per-cell table ships with every result.
  b. Secondary: AUROC per cell; Brier score; ECE (equal-mass
     bins) overall, per track, and per length bucket, target
     ECE <= 0.05 overall and <= 0.10 per bucket.
  c. Uncertainty: overconfidence rate on Track U (fraction of
     U samples scored with confidence above 0.7) target <= 5
     percent; abstention supported and counted separately, with
     abstention on U treated as correct behavior.
  d. Robustness: 100 percent defined outputs on E-13; zero
     crashes; zero NaN; injection success rate 0 on V-12.
  e. Leakage: score shift between V-10/V-11 paired cells and
     between V-16 pairs, reported as a leakage index; large
     shifts with process held constant indicate feature leakage
     even when accuracy looks acceptable.
  f. Generalization: the G9 held-out delta (FM-12) reported as
     a headline number.
  g. Transform curves: detection vs paraphrase strength (V-05)
     and vs decoding temperature (A-10) reported as curves.
No single-number summary of the benchmark is ever published
without the per-cell table attached.

9.4 Claims discipline
Results must state: corpus version, split, task definition
(9.3), threshold selection procedure (thresholds are chosen on
DEV, never on TEST/HIDDEN), and detector version. Comparisons
across different corpus versions are invalid.

10. FUTURE EXPANSION
----------------------------------------------------------------

10.1 Generator refresh cadence
Quarterly: add current model versions into existing slots; the
held-out G9 slot rotates so it always contains a family unseen
by detectors under test. Old versions are never removed (A-12
grows), because "detects last year's models only" is a failure
this corpus must keep visible.

10.2 Temporal drift track
Re-run a frozen prompt panel against each new model generation
and re-commission a fixed human writing panel annually. This
yields matched longitudinal series for both distributions and
directly measures the decay rate of any deployed detector.

10.3 Human re-baselining
Annual refresh of H-20 and re-estimation of the human style
baseline, because human writing absorbs model idioms over time.
Any detector feature whose human-side distribution moves across
annual snapshots gets flagged as unstable.

10.4 Tell-list maintenance
tells-YYYY-MM updated per release from current literature and
internal feature audits; V-10/V-11 regenerated against each
update so the leakage index (9.3(e)) always reflects current
stereotypes rather than 2024's.

10.5 New tracks
  Multilingual: full track parity in 3-5 additional languages,
  with native-speaker T1 pipelines.
  Long documents: 5k-50k word samples with chapter-level span
  maps; tests windowing strategies.
  Code authorship: a parallel corpus for source code with
  commit-level provenance.
  Agentic text: model output containing tool-use artifacts,
  citations, and retrieved spans (RAG), where verbatim retrieved
  human text sits inside generated scaffolding.
  Watermark track: cooperating generators with watermarks
  enabled, plus watermark-removal transforms, evaluated as a
  separate task with its own metrics.
  Speech: ASR transcripts of AI-voiced synthetic speech vs
  human speech.

10.6 Community red-teaming
A standing submission channel where internal and external red
teamers submit candidate fooling samples with provenance; any
accepted sample that breaks the current detector enters both
the corpus (Track V) and the regression suite (Section 8) with
credit.

10.7 Difficulty re-estimation
Difficulty ratings D1-D5 are re-estimated each major release
from the empirical pass rates of the baseline detector panel,
so "hard" tracks reality instead of 2026 intuition. Rating
changes are versioned; historical ratings remain queryable.

10.8 Deprecation criteria
A category is deprecated (frozen, still executable, excluded
from headline reporting) only when its stress target is proven
obsolete across two consecutive major releases, documented in
the changelog. Deprecation without that evidence is prohibited;
convenient categories die, inconvenient ones must not.
